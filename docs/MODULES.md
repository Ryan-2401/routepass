# 모듈 설명서 (팀원 공부용)

PDF 규칙상 **팀원 누구나 코드 동작을 설명할 수 있어야** 합니다. 아래처럼 4명이 모듈을 나눠 맡고, 자기 모듈은 "입력 → 처리 → 출력"을 말로 설명할 수 있게 준비하세요.

## 전체 흐름

```
[입력폼] 도시 순서·박 수·출발일
   │
   ▼
/api/plan ── 코드: 도시 좌표 찾기 → 여행금지 차단 → 날짜·구간 틀 만들기 → 인천 노선표로 직항 여부
   │         AI : 틀 안에서 하루 일정 + 구간별 이동수단 후보 + 검색할 환승 허브
   │         코드: AI 결과가 틀을 지켰는지 검사, 어기면 다시 요청
   ▼
화면에 일정 표시 후 동시에 진행
   ├─ /api/verify   이동수단마다 운행 여부 (저장된 사례 → 검색+AI → 확인 불가)
   ├─ /api/flights  항공권 (캐시 가격 → 버튼 누르면 실시간)
   └─ /api/places   식당 (OpenStreetMap 실제 목록 → AI가 그 안에서 선택)
   ▼
브라우저: 다익스트라로 최저가/최단시간/균형 경로 계산 (lib/pathfind.ts)
   ▼
/api/entry ── 최저가 경로 기준으로 체류일·비자·여행경보 검사 (AI 사용 안 함)
```

## 핵심 설계 원칙 (발표·보고서에서 강조할 것)

1. **AI가 사실을 지어낼 수 없는 구조**
   - 식당: AI에게 식당 이름을 쓰지 말라고 하고, 실제 지도 목록의 **번호**만 고르게 함 (`lib/server/places.ts`)
   - 운행 판정: AI에게 URL을 쓰게 하지 않고 검색 결과 **번호**만 고르게 함. 범위를 벗어난 번호는 버리고, 근거가 없으면 "확인 불가"로 강제 (`lib/server/verify.ts`)
   - 일정: 날짜·도시 순서·구간 수는 코드가 정하고 AI 결과를 검사, 어기면 오류 내용을 알려주고 재요청 (`lib/server/planner.ts`, `lib/server/gemini.ts`)
2. **틀리면 위험한 판단은 AI에게 맡기지 않음**
   - 비자·체류일·여행금지는 규칙 엔진(`lib/entry.ts`)과 출처 있는 데이터로만 판정
   - 외교부 여행금지 국가·지역은 AI 호출 전에 코드가 막음
3. **가격은 AI가 아니라 데이터와 알고리즘**
   - 항공 가격은 API 결과, 경로 선택은 다익스트라 (`lib/pathfind.ts`)
   - AI는 "어느 허브를 검색할지"만 제안 → 무료 쿼터 절약
4. **출처와 확인 날짜를 항상 표시**, AI가 만든 내용에는 "AI가 생성한 내용" 표시

## 팀원 분담안

| 담당 | 파일 | 설명할 수 있어야 하는 것 |
|---|---|---|
| A. 일정 생성 | `lib/server/planner.ts`, `lib/server/gemini.ts`, `lib/server/resolve.ts`, `lib/incheon.ts` | 프롬프트 구성, JSON 스키마 검증과 재요청, 박 수 배분, 직항/운휴 판단, 여행금지 사전 차단 |
| B. 운행 검증 | `lib/server/verify.ts`, `data/transport-kb.json`, `scripts/experiment.ts` | 지식베이스 매칭 규칙, 검색어 만들기, 번호 기반 근거 선택, 비교 실험 방법과 결과 |
| C. 항공·경로 | `lib/server/flights.ts`, `lib/pathfind.ts` | 캐시 vs 실시간 가격, 쿼터 관리, 그래프 만들기(허브 노드·별도 발권), 다익스트라, 3가지 목적 함수 |
| D. 출입국·화면 | `lib/entry.ts`, `lib/server/mofa.ts`, `app/page.tsx`, `components/*` | 쉥겐 180일 중 90일 계산, 연속 체류 묶기, 러시아–벨라루스 규칙, 오류·로딩 화면, AI 표시 |

## 파일별 요약

### lib/server/planner.ts — 일정 생성
- `banBlock`: 여행금지 국가/지역(쿠르스크주 전체 등)이면 일정 생성 거부
- `allocateNights`: 박 수를 비운 도시는 전체 일수에서 나눔
- `skeleton`: 도착·출발 날짜와 구간(인천→…→인천) 틀
- `buildPrompt` / `checkAiPlan`: AI에게 틀을 주고, 결과가 틀(도시 수·날짜·구간·허브 후보)을 지켰는지 검사
- 키가 없으면 `data/demo/plan.json` 예시 사용

### lib/server/verify.ts — 운행 여부
- 1순위 `matchKnowledgeBase`: 출처로 확인한 사례. `keywords`(예: 알레그로)는 어느 구간에서 나와도 적용
- 2순위 `judgeWithSearch`: Tavily 검색 → Gemini가 번호로 근거 선택
- 상태 5가지: 운행 중 / 조건부 운행 / 최근 변경 / 운행 중단 / 확인 불가

### lib/server/flights.ts — 항공권
- Travelpayouts: 최근 2~7일 다른 사람들의 검색 기록 기반 캐시 가격 (실시간 아님)
- SerpApi: Google Flights 실시간 결과, 버튼 눌렀을 때만
- 키가 없으면 데모에서 "예시 가격" (화면에 실제 아님 표시). 인천 노선표에 직항이 없으면 예시에도 직항을 안 만듦

### lib/pathfind.ts — 최저가 경로
- 노드: N0(인천) … Nn(귀국 인천), 허브 경유는 `IST@0` 같은 중간 노드
- 간선: 항공권 결과, AI 추정 지상 이동(운행 중단 제외)
- 목적 함수: 가격 / 시간 / 균형(1시간 = 15,000원)

### lib/entry.ts — 출입국 규칙 엔진
- 같은 나라 연속 체류는 한 번의 입국으로 묶음
- 쉥겐: 입국일·출국일 포함, 180일 창에서 최대 일수
- 나라별: 1회 최대 체류일, 180일 중 합계, 사전허가(ETA/ESTA), 규칙 유효기간
- 러시아–벨라루스: 체류 합산 안내, 육로 이동 경고
- 별도 발권 환승 국가 비자 확인

## 데이터를 고칠 때
- 모든 규칙에는 `sources`와 확인 날짜를 남기세요.
- `entry-rules.json`의 `confidence`: verified(출처 확인) / baseline(재확인 필요) / unknown(앱이 판단 안 함)
- 새 운행 사례를 찾으면 `transport-kb.json`에 추가하고, 정답 세트(`data/eval`)에도 넣으세요.

## 알려진 한계 (보고서 "한계와 개선 방향"에 쓸 것)
- 여행금지 "국경 30km" 구간은 좌표로 정확히 판정하지 못해 해당 주(州) 전체에 경고를 띄움
- Travelpayouts 캐시는 누군가 최근에 검색한 노선만 있음 → 러시아·벨라루스 구간은 비어 있을 수 있음
- 장거리 비행의 도착일이 다음 날이 되는 경우를 일정 날짜에 반영하지 않음
- 이번 여행 전 180일 안의 쉥겐 체류 이력은 입력받지 않음
- 메모리 캐시는 서버가 재시작되면 사라짐
